# Validation Checklist

Before delivering, verify all applicable checks pass.

## Universal checks

- [ ] Every factual claim is backed by a web source fetched during this session — no training-knowledge-only claims
- [ ] Executive summary is within the budget in `report-assembly.md` — about 10% of the report's total
      length, capped at 1,500 words — and reads as a standalone document
- [ ] No padded sections: every section carries researched findings, none restates another, and no
      section was written thin to hit a structure count (`report-assembly.md` → "No padding")
- [ ] Report length is within the mode's target range in `report-assembly.md`, or shorter with the
      shortfall explained in Limitations
- [ ] Every major claim has at least one citation
- [ ] At least 70% of citations are HIGH or MEDIUM credibility
- [ ] Limitations section is present and honest
- [ ] No unsubstantiated superlatives without data
- [ ] References have valid URLs
- [ ] Source count meets mode minimum
- [ ] Sources come from at least N unique TLDs (quick:5, standard:8, deep:12, ultradeep:15)
- [ ] No single domain accounts for >30% of citations
- [ ] Report is in the same language as the user's question

## HIGH-risk domain checks (health, finance, legal)

- [ ] Every domain-specific claim has a preferred-source citation
- [ ] Domain-appropriate disclaimer is present
- [ ] Misinformation flags section exists (even if empty)
- [ ] No claims contradict institutional consensus without explicit flagging

## Iteration documentation

- [ ] Number of waves documented in Methodology
- [ ] Termination reason documented (saturation / wave-cap / time-cap)
- [ ] Source accessibility breakdown documented

If validation fails, do targeted follow-up research to fill gaps.
